For current setup and operation, use the [production guide](PRODUCTION_EVALS_GUIDE.md). This document records the design and scope.

Status: implemented and locally qualified; physical fleet and customer production qualification remain operator-owned. ## Research and scope

Extend existing imports, native scoring/trace execution, release policies, checkpoint recovery, human review, judge calibration and CLI checks. Sources: accessible sections of [Building eval systems](https://www.lennysnewsletter.com/p/building-eval-systems-that-improve) and [Advanced evals](https://www.lennysnewsletter.com/p/advanced-evals-how-to-find-and-fix); Apple's [Designing effective evaluations](https://developer.apple.com/documentation/Evaluations/designing-effective-evaluations), [Evaluating prompts](https://developer.apple.com/documentation/foundationmodels/evaluating-prompts-to-measure-performance-and-improve-model-responses), [WWDC25 prompt design and safety](https://developer.apple.com/videos/play/wwdc2025/248/), and [Foundation Models SDK for Python](https://apple.github.io/python-apple-fm-sdk/index.html). Production evaluation needs representative real examples, measurable full outcomes, isolated validation data, repeatable automated runs and validated graders. Paid article endings were unavailable. These are requirements, not production qualification claims.

Deliver a local-first production workflow usable by an individual or a team with a shared trusted storage directory. No hosted service, credentials export, implicit production-data capture or automatic replay of uncertain side effects. Eligible Apple machines execute Apple's model; external workers can invoke a developer-owned native executable or registered app integration. Device/model descriptors are reported provenance, not hardware attestation.

## Frozen acceptance contract

1. Immutable, content-addressed JSONL datasets support at least 10,000 examples. Preserve stable source IDs, development/regression/test partitions, task/locale/cohort metadata and optional captured outputs/feedback. Reject duplicate IDs, malformed or oversized records and contradictory source partitions. Dataset and execution revisions bind every result. Production import requires explicit redaction confirmation; SDK capture is disabled until configured with a sanitizer and an approved metadata allowlist.
2. Durable jobs process bounded chunks, preserve every committed result, and resume remaining work after restart. Stable request IDs and atomic per-chunk leases support multiple worker processes. Expired ownership cannot commit. Pause/cancel do not erase evidence. Pure inference can retry transient failures within explicit limits; an uncertain side-effecting attempt becomes needs-evidence and requires explicit reconciliation. Budget/deadline/worker target mismatches fail closed.
3. Worker execution is usable without the desktop connector: a command-line client imports data, creates jobs, executes a trusted supplied worker executable, controls/resumes jobs, exports reports and returns meaningful qualification exit codes. The desktop supplies a native worker using the existing EvaluationRunner and frozen suite setup. Worker registration/heartbeats and target metadata support Apple hardware/OS/locale matrices. No fallback to a different device/provider.
4. Production capture uses an opt-in SDK JSONL exporter and confirmed import. It retains feedback/source dimensions for representative versus targeted discovery. Captured outputs can be reviewed without regeneration. Local retention/export controls expose the actual storage boundary; external publishing remains developer-owned.
5. Reports stream chunk evidence, show completeness, sample outcomes, distinct-source Wilson intervals, latency percentiles and metadata cohorts, and compare compatible frozen datasets/scoring contracts. Repetitions do not inflate independent evidence. Discovery datasets never claim production prevalence. Release thresholds include error limits, critical cases, pass-rate/latency limits and cohort thresholds. Missing/unscored/uncertain evidence cannot pass. Existing suite policy is translated explicitly.
6. Human review assignments, labels, notes, reviewer identity and disagreement resolution have an append-only audit history keyed to the exact captured result. Held-out data remains marked and never enters model prompts automatically. Quality/safety/unhappy-path coverage is metadata-driven, and reports expose missing required cohorts.
7. UI uses the existing sidebar, WorkspacePaneLayout, panels, search fields, typography and semantic colors. Batch runs is a visible sidebar destination; Datasets, Jobs, Review, Reports and Workers use the existing progressive layout. File import previews and explicit confirmations precede mutations. No new palette or global layout.
8. Tests qualify 10,000 fixture examples, bounded chunking, restart/resume, duplicate execution prevention, stale leases, transient retries, uncertain actions, dataset immutability, cohort statistics, gate completeness, privacy capture and CLI integration. Independently review stable source scopes and inspect actual native UI. Run a small real on-device smoke test when the model is available. Fixture throughput does not qualify a physical fleet, actual production traffic or a release.

## Design

Pure Foundation/CryptoKit production contracts and storage live in Packages/ProductionEvals and are exposed as an independent portable Swift package. A job freezes its dataset digest, repetitions, retry/timeout/budget policy, target matrix, release policy and opaque execution setup. Chunk checkpoints are bounded to 100 slots; datasets are streamed. File-system locks protect mutations across processes; job results and lease owner tokens bind commits. Administrative controls and human audit records are independent of worker evidence.

The CLI requires an explicitly supplied absolute executable path for custom workers; it sends one JSON request on stdin and accepts one bounded JSON result on stdout, enforces timeout, and never runs shell text. The app worker reuses existing native scoring and execution setup. Multi-process workers coordinate through trusted shared storage; polling workers launch due jobs and claim only matching target slots; scheduling does not infer device availability.

## Qualification and limits

Single-machine fixture capacity and native UI/source checks are separate from live Apple model, physical-device matrix and real production ingestion evidence. Capture sanitization is developer-defined and must be reviewed by the integrating team. File-system coordination requires coherent atomic local/shared storage semantics; object stores and eventually consistent mounts are unsupported. Authenticated hosted collaboration, fleet provisioning and customer production deployment are separate operational deployments, not silently created by this feature.
