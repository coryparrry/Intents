## Implementation plan

1. **M1:** Freeze reusable requirements separately from execution evidence and profile; add canonical contract hashing, typed comparison, legacy preservation and a before/after regression.
2. **M2:** Add an awaitable snapshot runner and one leased, durable plan across selected routes. Negotiate oracle-free inputs, bind build/fixture/sample identities, and retain failed, cancelled and late evidence.
3. **M3:** Use the compiled declaration for action and feature choice. Make one expectation edit update its observation, projection, claim and assertion together; connect setup and capability guidance to the built UI.
4. **M4:** Complete the production Notes summary integration, retain Tasks controls, and add durable collections and honest full/partial reruns. Capture an unchanged-contract fix/retest record.
5. **M5:** Extract the minimum shared report policy and ship a bounded, offline evidence bundle checker with external trusted requirements. Exercise documented controls and commands.
6. **M6:** Qualify the exact source on available native paths and prepare the independent existing-app exercise; record unavailable hardware or human checks separately.

Each milestone gets focused regressions, integrated validation, a scoped review and a dependent PR. Do not mark an ID passed from a build alone or from an earlier source revision.

## Material design deviations and limits

- The installed Xcode 27 SDK offers `IntentDefinitions` lookup by known ID, not public enumeration. The guided picker uses the integrity-bound compiled app declaration, then checks support and actual observations at execution.
- A coordinated run owns one frozen plan and a shared admission lease, while selected native routes execute as individually journalled XCTest children. This retains independent route/attempt evidence within the existing coordinator authority boundary.
- The offline command requires an externally supplied expected app digest in addition to trusted requirements, source revision and policy. The specification's sample command was illustrative; this extra pin prevents a self-consistent bundle from choosing its own app build.
- The installer default points to a verified published PR commit. If the stack is later squash-merged or repackaged, reverify and repin the durable merged package revision before releasing the app.
- The generated Basic integration remains a read-only v2 direct check because it does not observe fixture content or business outcomes. Stable v3 qualification requires an app-owned fixture observer and actual observed result. Source labels use `git:<SHA>` for a clean checkout or `inputs-sha256:<digest>` for dirty/non-Git builds; the checked executable digest remains independently pinned.
- Physical Siri outcome, an actual supported-model Notes summary, notarized distribution qualification, and independent human adoption remain separate from source, simulator and local checker results. A Developer ID signed review DMG exists, but it is not notarized or Gatekeeper accepted.
