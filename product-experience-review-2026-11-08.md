## Third pass — new findings

**P2 — A failure-pattern drill-down can include non-failures.** Give the same tag to a confirmed failure and to a passed or needs-evidence review, then select a sample in the pattern or **Show all examples**. [Patterns](FoundationEvals/FoundationEvals/Services/EvaluationReviewWorkflow.swift#L261) counts only current human-confirmed failures, but [navigation](FoundationEvals/FoundationEvals/Views/SuiteReviewView.swift#L31) supplies only the tag. The [sample list](FoundationEvals/FoundationEvals/Views/SuiteReviewView.swift#L61) defaults to all verdicts and filters by that tag, so it can show extra passed or needs-evidence reviews beyond the card's failure count. Users can manually choose **Human failures**, and each row displays its verdict, but the drill-down does not preserve the set it promised. Carry the failed-verdict filter with the tag, or clearly distinguish the broader tag view. Verify shared tags across verdicts and switching filters. **Status:** source-established conditional path; not exercised in the UI.

**P2 — Switching batch results discards unfinished operator-review input.** In a batch result's **Operator review**, type an explanation, tags, assignee or reconciliation output, then select a different result or change page before recording the action. The inputs are [local view state](FoundationEvals/FoundationEvals/Views/ProductionResultDetailView.swift#L3); [changing selection](FoundationEvals/FoundationEvals/Views/ProductionReviewPane.swift#L44) replaces the detail view and resets those fields. Only a submitted action is sent to [persistent audit storage](FoundationEvals/FoundationEvals/Stores/ProductionWorkspaceStore.swift#L395). After a submitted action is saved successfully, reselecting that result reloads its audit entry; an unfinished explanation or verified output must be re-entered. Preserve per-result drafts or offer a clear discard/cancel choice when leaving a dirty form; test selection, pagination, failed writes and reopening. **Status:** source-established; no UI or persistence-failure reproduction.

## Second pass — new findings

**P1 — An imported Siri result can be shown as current for unsaved edits.** Export or run a scenario, then edit an expectation without saving and import the earlier result bundle. Changes retain the saved revision until [Save](FoundationEvals/FoundationEvals/Stores/SiriStudioStore.swift#L54), while [Import result bundle](FoundationEvals/FoundationEvals/Stores/SiriStudioStore.swift#L134) passes the unsaved document directly to the importer. If the scenario and turn IDs, turn count, repeat count and asserted metric types still match—for example, an argument value changes—the [evidence matcher](Sources/MacIntentTesting/SiriStudio/SiriStudioReport.swift#L105) accepts the old revision and the [imported record](Sources/MacIntentTesting/SiriStudio/SiriStudioRunner.swift#L180) freezes the edited document. The [stale check](FoundationEvals/FoundationEvals/Stores/SiriStudioStore.swift#L152) compares that frozen copy to the same edited document, so a previously passing verdict can appear current even though the edited expectation was never run. The existing [stale-evidence test](Tests/MacIntentTestingTests/SiriStudioReportTests.swift#L59) increments the revision explicitly and does not cover an unsaved edit. Save and revision the document before importing and fail safely if saving fails; this guards edits against the current saved baseline but does not distinguish independently edited copies with the same ID and revision. Bind evidence to a content digest or the actual authored snapshot rather than relying on a revision alone. Verify changed arguments, unchanged metric types, save failure, reopening the imported record, and independently edited copies. **Status:** source-established conditional path; not reproduced in the UI or against Xcode. Uncommitted Siri Studio only.

**P2 — A batch report invents a baseline change when no pass rate exists.** Create a batch with a compatible completed baseline, then open its report before any response is scored, or after only unscored/error responses. The candidate [pass rate](Packages/ProductionEvals/Sources/ProductionEvals/Models/ProductionReports.swift#L14) is unavailable, but the [report display](FoundationEvals/FoundationEvals/Views/ProductionReportPane.swift#L25) substitutes zero when calculating the percentage-point change. A 90% baseline can therefore appear to have fallen by 90 points even though there is no scored candidate result. The [analysis](Packages/ProductionEvals/Sources/ProductionEvals/Services/ProductionAnalysis.swift#L150) separately marks missing or unscored evidence as ineligible, so this is a misleading display rather than a passing release gate. Display a change only when both rates exist; otherwise say the comparison is unavailable. Verify pending, unscored, error-only, and genuinely zero-percent cases. **Status:** source-established; report rendering not tested.

**P2 — Removing a Siri turn also removes its expectations without a confirmation.** With two or more turns, [Remove turn](FoundationEvals/FoundationEvals/Views/SiriStudio/SiriStudioConversation.swift#L18) immediately deletes the turn object, which contains its utterance and [expectations](Sources/MacIntentTesting/SiriStudio/SiriStudioDocument.swift#L82). There is no confirmation or structural undo in the examined Studio controls. Once the user saves, exports, or starts a run, the edited document can replace the prior saved copy; a separate export or earlier run may retain older evidence. Scenario deletion does have a confirmation. Offer undo or confirm removal with the scope of lost expectations. **Status:** source-established behavior; native Undo behavior and actual interaction not tested. Uncommitted Siri Studio only.

## Earlier findings and priorities

The following were independently checked in this working tree and were already documented in [the earlier follow-up review](product-review-followup-2026-11-08.md); they are carried forward, not newly discovered.

1. **P1 — Unsaved Siri scenario edits can be lost.** Edit a scenario, then open another valid scenario document: [the action](FoundationEvals/FoundationEvals/Views/SiriStudio/SiriStudioView.swift#L235) calls [openDocument](FoundationEvals/FoundationEvals/Stores/SiriStudioStore.swift#L67), which adopts the new document without preserving or warning about edits. Closing also cancels work without saving ([close](FoundationEvals/FoundationEvals/Stores/SiriStudioStore.swift#L162)). Pressing Save and choosing another app are safeguards ([save control](FoundationEvals/FoundationEvals/Views/SiriStudio/SiriStudioView.swift#L98), [app selection](FoundationEvals/FoundationEvals/Views/MacIntentTestingView.swift#L37)); the guide explicitly requests a save. A user can still lose lengthy edits. Show dirty state and Save/Discard/Cancel or preserve an autosaved draft, including on quit and save failure. Source-established; runtime not reproduced. Applies to uncommitted work.
2. **P1 — Results can overstate incomplete or incomparable runs.** The [headline](FoundationEvals/FoundationEvals/Views/SuiteResultsView.swift#L56) reports a scored pass rate without planned coverage beside it; the [trend](FoundationEvals/FoundationEvals/Views/SuiteResultsView.swift#L161) compares consecutive scored runs without applying the separate [compatibility-aware baseline selection](FoundationEvals/FoundationEvals/Views/RunAnalysisSection.swift#L3). A partially completed run or a changed test set can look like an improvement. Show scored/planned counts and completion at each summary, and require compatible evidence for a directional delta. The detailed run view contains additional context. The standalone plugin independently repeats the scored-only comparison in its [history view](plugins/apple-foundation-evals/ui/native-results.js#L55). Source-established; runtime rendering not checked.
3. **P1 — Archive lacks a discoverable return route.** The sidebar filters archived suites and provides an Archive action ([sidebar](FoundationEvals/FoundationEvals/Views/WorkspaceSidebar.swift#L92)); the store records an archive date and protects the last active suite ([store](FoundationEvals/FoundationEvals/Stores/EvaluationStore.swift#L670)). The earlier review found no restore UI. Expose archived projects and suites with restore, preserving history, and test conflicts. This is not evidence of deletion. Source-established for examined routes; further alternate-entry audit pending.
4. **P2 — Standard backup guidance omits separate test evidence.** The [data guide](docs/wiki/Data-and-troubleshooting.md#L5) directs users to the FoundationEvals Application Support folder, while [Siri Studio](FoundationEvals/FoundationEvals/Stores/SiriStudioStore.swift#L21) defaults to a separate `Intents/SiriStudio` root and its [own guide](docs/wiki/Siri-Studio.md#L55) names it. Direct Action also writes logs and result bundles under a [separate root](FoundationEvals/FoundationEvals/Stores/MacIntentTestingStore.swift#L125), which this pass independently identified. A user following only the central guidance can miss scenarios and test evidence in a move. Provide an explicit complete backup and restore procedure including credentials and settings boundaries; test on isolated data. Source-established; no restore performed. Siri Studio is uncommitted; the Direct Action storage path already exists at the reviewed commit.

5. **P2 — A failed save can leave Siri app selection unexplained.** When choosing another app, the current scenario is saved first. If that fails, [the catch](FoundationEvals/FoundationEvals/Views/MacIntentTestingView.swift#L37) writes a native-store diagnostic, but the active [Siri panel](FoundationEvals/FoundationEvals/Views/SiriStudio/SiriStudioView.swift#L19) reads the Studio diagnostic instead. The draft remains intact, yet the chooser can appear to do nothing. Show the error in the active mode and offer retry. Source-established conditional path; no injected write failure; uncommitted feature.
6. **P2 — “Blank suite” contains a scored example.** The [picker](FoundationEvals/FoundationEvals/Views/WorkspaceManagerView.swift#L127) uses the [default suite](FoundationEvals/FoundationEvals/Models/EvaluationModels.swift#L271), which contains an example case. Importing own cases can leave this unrelated case in the run and affect results. Start truly empty or name the example explicitly and prompt the user to replace it. Source-established; first-use interaction not run.
7. **P2 — A capacity-limited import hides the omitted count.** The [import preview](FoundationEvals/FoundationEvals/Views/CaseImportView.swift#L53) validates rows and correctly labels the number that fits; the [capacity calculation](FoundationEvals/FoundationEvals/Views/CaseImportView.swift#L179) limits the inserted rows without making the source total and omitted count clear. Show both counts and a continuation path to avoid accidental partial datasets or duplicate reimports. Source-established; no file import exercised.
8. **P2 — Scheduled batches are difficult to distinguish and guidance conflicts.** [Schedule rows](FoundationEvals/FoundationEvals/Views/ProductionWorkspaceView.swift#L243) identify only interval and remaining count, so matching rows can be confused; they say an unattended worker is required. The [troubleshooting guide](docs/wiki/Data-and-troubleshooting.md#L83) also says a running app suffices, while examined tick call sites are workers, CLI and MCP. Name the template and next due time, and clarify how jobs are ticked and executed. Source-established; real scheduling and downtime untested.

These are carried forward from the earlier report and independently checked against the current source. The plugin history behavior in finding 2 and Direct Action storage boundary in finding 4 are additional evidence from this pass.

## Strengths and product assessment

A native, local-first workbench that joins repeatable cases, traces, saved evidence and human review offers a strong reason for Apple-platform developers to return after each model, prompt or app change. Document draft persistence, explicit cancellation, retained evidence and compatibility-aware analysis are useful safeguards. The strongest reason to leave is loss of trust when a prominent summary can hide incomplete coverage, or when authored work and archives are difficult to recover. These are product hypotheses drawn from source, not user or retention data. Ask a small set of target developers to complete a first evaluation, change a case, compare runs and restore an archived suite without coaching; record where they hesitate and what they believe the numbers mean. No pricing, demand or conversion claims are inferred.
